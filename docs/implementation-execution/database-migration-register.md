# Database Migration Register

The documentation-only authorisation created no migration file. The subsequent
authorised IR-002 implementation created only the two paths recorded below.
`DBM-*` identifiers are stable logical ownership units, not SQL filenames. A
unit has one owning IR; a later packet may consume its evidence but cannot take
ownership. Schema, data, policy, Storage, Realtime, and generated-type work are
deliberately separated.

## Ordering controls

- DBM-001–005 and DBM-007–010 are schema/data-model planning units.
- DBM-006 is the base policy unit; DBM-012 only sequences migration-stage
  activation after Storage, Realtime, and supporting policies are independently
  ready.
- DBM-011 is data transformation, not a substitute for destination constraints.
- DBM-013 is a serial generated-type refresh checkpoint. It cannot run ahead of
  schema provenance or mask a failed migration/policy review.

IR-002 approves the existing three-digit sequence only for
`006_ir002_tenant_root.sql` and `007_ir002_configuration_archive_audit.sql`.
No later packet inherits this naming authority.
